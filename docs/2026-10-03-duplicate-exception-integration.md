# Typed duplicate exception dependencies

## Intended next boundary

Connect automatically derived duplicate evidence and human pair comparisons to the existing shared exception workflow. This preserves the distinction between source evidence, advisory work and financial acceptance. No automatic verdict, resolution flag, charge, source publication or assignment-blocker rewrite is introduced.

A private trigger on a new invoice-field review examines the latest review of each other logical source in the same organization/scope, selecting heads before any scope or match filter. It uses the migration 0106 evidence function without audience filtering. Matching pairs, including identical-source invoice/credit conflicts, produce typed retained dependencies. Hidden pairs remain hidden through the intersection of all retained source audiences; discovery is never exposed as a global count or a client-controlled hash lookup.

For each matching pair, the lower logical UUID is the deterministic anchor. The case is identified by organization, scope, cause `duplicate_candidate` and the anchor's exact extraction revision. Multiple matching reference sources and corrected field reviews share that case while its anchor extraction stays unchanged. A newer anchor extraction has a new case. A typed `duplicate_exception_dependency` pins both exact field reviews, logical sources, source references and the derived match evidence. The canonical pair of exact review IDs is unique, including when the trigger sees the pair from either direction. Composite FKs and a validation trigger establish anchor/case/review provenance; client runtimes cannot insert or mutate dependencies.

Initial backfill derives only currently matching review heads. It does not invent historical human judgments. Later nonmatching corrections preserve prior cases and evidence; they do not silently resolve them. Financial adoption must independently compute current applicability.

## Events and access

A new dependency atomically appends an automatic `duplicate_evidence_added` event, reopens attention and preserves an advisory claimant. A retained human comparison atomically appends `duplicate_comparison_recorded` for its exact dependency. This is an automatic observation of an existing immutable human record: its actor and explanation remain available through the comparison, while the automatic event itself has no client request or actor identity. It reopens attention and does not disposition all dependencies. Historical comparison backfill links only comparisons whose exact review pair has a proven retained dependency; unmatched historical comparisons remain accessible through their existing pair API.

The two new event variants have explicit mutually exclusive typed references. An event validation trigger verifies the comparison/dependency/case relationship, including reversed orientation. Existing assignment/context event contracts and old receipts remain intact. Domain triggers serialize under the existing shared ACL then exclusive financial-input lock, so concurrent discoveries/comparisons cannot fork event chains. Comparison API requests do not acquire authority over the whole shared case or reveal its ID: an automatic observation can update a case that is unreadable to that actor, while the pair command still requires both exact sources and destination prepare.

Case reads, lists, history, dependency counts and replay require every retained duplicate source audience, in addition to the existing anchor/context audiences. Advisory case writes additionally require prepare for all retained duplicate sources and destination, including after a replay request. A private/general case-work helper exposes only a boolean for already readable cases. Adding a hidden dependency may therefore make a formerly readable case inaccessible; no prior counts or partial history survive a fresh read.

## Interface and qualification

Extend case responses with bounded typed duplicate-dependency pages, exact source/review references and linked comparison details. Keep assignment-dependency responses compatible. The UI labels automatic detection separately from manual comparison, shows both sources and stored replacement direction, and links to exact source/extraction views. It must not interpret a recorded comparison as case resolution. Existing claim/release/snooze/reopen UI retains immutable request retries and current audience checks.

Tests must cover automatic initial detection, reversed discovery deduplication, new revisions reopening snoozed attention, source-kind conflicts, nonmatching corrections retaining history, invisible reference intersection, access revocation before historical replay, every-source prepare, actual-role restrictions, pair/comparison/event provenance, immutable/FK constraints, concurrent event ordering, atomic rollback, populated downgrade refusal, backfill idempotence and coverage. Reuse the existing pair qualification; do not claim financial duplicate prevention. Tax/eligibility, adoption, release, cross-scope allocation and the unprocessed-receipt readiness boundary remain pending.

## Independent review refinements

Canonical orientation follows logical IDs, including the stored evidence; review UUID ordering does not select the anchor. Discovery verifies that its triggering review is still the latest head and never silently truncates matches. Detection events are unique per dependency; comparison observations are unique per immutable comparison, allowing several comparison revisions on one dependency. Access helpers inspect private underlying tables with RLS disabled to avoid recursion. Migration acquires organization ACL/financial locks in deterministic order before source-table locks and head enumeration; observation timestamps represent linkage time. Any observation failure rolls back the comparison, with no hidden case metadata in its response. Qualification includes three-source overlapping cases, repeated backfill, hidden evidence added to a snoozed case and injected observation failure. Uploader-only custody can make a multi-uploader shared case unreadable to all ordinary source users; this milestone does not widen access or clear it.
