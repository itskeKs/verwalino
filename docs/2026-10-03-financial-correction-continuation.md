# Continuing financial corrections

## Bounded deliverable

Expose creation and recovery of the existing immutable-original correction workflow on WEG annual-settlement and asset-report pages. A finalized original links to its existing successor; an unknown create response requires reading the original to determine its outcome. A recovered successor is opened explicitly. Creating a draft does not finalize or complete any correction impact.

A WEG draft may explicitly adopt the current finalized successor of its linked economic plan. A bounded, cycle-checked chain must preserve property, exact scope, mandate, period, plan year and due day, with live access to every hop. Show the eligible candidate first, then require deliberate acknowledgment and a reason. No arbitrary plan replacement or automatic adoption is allowed. Hold the financial input/ACL locks, compare the expected linked plan, revalidate the chain and clear obsolete draft calculation output atomically with the link and audit. Existing coverage and computation evidence remains retained but becomes stale. Repeating an already-applied identical plan transition must not clear a later computation or create another audit effect.

Qualification: actual plan and WEG correction/recompute/finalization, source/coverage invalidation, original hash preservation, draft/finalized/context/scope/tenant/rights boundaries, chain bounds, concurrent/repeated transition and rollback. UI tests cover explicit selection and lost responses; browser qualification covers both correction controls and linked-plan adoption. No new migration or live-provider operation is planned. Full B3 and specialist release gates remain open.

## Accepted continuation

Implemented the draft-only preview and selection endpoints with ACL → financial-input → draft-row locking and at most 100 accessible finalized plan hops. The chosen head must preserve the original plan's obligation context and exact accounting scope. Selection checks the expected link, clears old draft lines/snapshot/totals and records an audit event in one transaction. An already-applied transition rechecks live authority and the current chain, then returns without erasing a newer computation or adding another audit event. A later plan successor requires a fresh review; this command does not promise historical replay after the eligible head changes.

Both WEG and asset-report pages expose deliberate correction creation and an explicit original-read recovery after uncertain responses. The plan selector retains the exact uncertain request, prevents competing financial commands, and clears its copied candidate on authoritative refusal. Navigation and successful plan adoption reset manual inputs and coverage review; late responses from earlier page loads and financial commands are ignored.

Independent read-only review found no concrete blocker in the service/API/UI boundary and requested chain, access, rollback, concurrency and lost-reply qualification. Those cases are included below. Browser qualification then exposed duplicate sibling React keys, which remounted/duplicated the plan selector. Distinct keys and a complete WEG-page integration regression repair that issue. The reviewer did not execute tests.
