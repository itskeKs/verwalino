# Immutable human invoice field reviews

Migration 0103 adds a human field-review revision before allocation and financial adoption. This advances B3 without accepting its unresolved financial and duplicate requirements.

Each review pins one exact assignment proposal. Its original, logical source, reviewed partition, extraction and destination scope are copied from that proposal and bound by a composite foreign key. A separate extraction/hash key binds the unchanged bytes. New reviews require that this is still the latest assignment and references the current partition and latest usable extraction. A newer failed extraction also invalidates a new review based on an older success. An inaccessible successor proposal returns denial instead of disclosing its presence through a stale-version response.

The version chain retains every earlier human review, actor, timestamp, reason and original extraction. Values in a review are explicit human assertions. They do not inherit field-level quotations or confidence from extraction merely because they share a source. A complete field acknowledgement covers only the specified invoice fields; it does not approve destination identity, tax treatment, duplicates, credit relationships, embedded XML/attachments or financial release.

The initial field contract requires seller name, document number, invoice/credit-note type, EUR currency, invoice date, explicit service-period dates and signed gross amount. Invoices are positive and credit notes negative. Money uses decimal strings and `NUMERIC(14,2)` bounds; excess precision is rejected before storage, never rounded into a different value. VAT amount/rate may remain unknown. Unknown VAT is distinct from zero; no amount or rate is inferred. A supplied VAT amount must have the document's sign (or be zero) and cannot exceed its gross magnitude. Dates are explicit ISO calendar dates bounded to years 0001–9999, with service start no later than end. A later service period is not rejected merely because it follows the invoice date. Document numbers are bounded without silent truncation; surrounding text whitespace is normalized.

Commands use the actual interactive role, current original prepare and destination read/prepare authority, the established transaction locks, an immutable request key/digest and exact previous review UUID. Authority is checked before historical replay. Replaying a prior command returns its original receipt after newer evidence without promoting it to current. Source-security pause blocks writes/replay. Reads inherit original-and-target access. There is no cost, source-release, assignment-state, exception-resolution or learned-mapping effect.

The access-coverage manifest includes the review ledger. No historical human reviews are fabricated during migration. Populated downgrade is refused and empty downgrade preserves the manifest function's identity. Tests of older migrations explicitly remove the newer schema inside rollback savepoints.

## Field-review interface

The source review page now includes a persistent field-review form and the latest 20 readable human revisions. Initial extraction values remain proposals. Document type and currency require explicit selection; absent periods remain empty. Unknown VAT is retained as null, distinct from zero. Decimal input accepts a comma or point and is serialized as an exact decimal string without floating-point conversion. Credit signs must be entered explicitly. Any field edit clears the acknowledgement. A previous human review can supply start values on the same assignment basis, but every new review needs a new acknowledgement and reason.

Unknown POST results retain the exact body, key and predecessor through transient source/parent reads. Conflicting drafts remain visible until the user explicitly replaces them with current start values. Current capability is tied to the readable proposal, and the database command rechecks the complete authoritative basis. Source denial clears the parent view and private field history. None of these actions clears a context blocker or confirms a cost.
