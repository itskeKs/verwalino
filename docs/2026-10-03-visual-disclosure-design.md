# Exact visual extract disclosure

Status: implemented and locally qualified as migration 0118. This increment does not accept B3 or M-B.

A disclosure publishes one previously generated visual artifact to one deliberately selected accounting scope. It creates no financial source or cost and grants no access to the original, private intake fields, preparation reasons or other pages. Each destination must receive its own explicit review and current authority check. Whole-original adoption remains unchanged.

The publisher must retain original custody/export, a current inspected partition containing the artifact's exact logical member, and destination read/prepare/approve/export grants. The command binds the exact artifact SHA-256, destination, expected disclosure head, explanation and explicit acknowledgment that the actual generated pages were checked for this destination. Before publishing, the service rereads and verifies stored derivative bytes; a separate trusted attestation binds that observation to the command, actor, database process and transaction. A checked box cannot substitute for an exact byte binding or destination authority.

Use immutable publication/withdrawal events with a bounded versioned chain for each artifact and destination. An expected head prevents concurrent conflicting transitions; actor/request-key receipts support exact historical retries after live reauthorization without reactivating withdrawn content. Only the current publication permits download. Republish after withdrawal requires a new explicit review and the current source basis.

Select the true latest head before applying audience filters. Historical publish replay returns the original sanitized receipt and reports current availability separately, without creating another attestation or publication. New publication binds the artifact's exact reviewed partition and inspection basis; a changed partition requires a newly generated artifact. Once published, the retained derivative has independent destination authority: later partition changes or uploader departure do not silently revoke it. Destination grants and explicit withdrawal govern its availability.

Withdrawal reduces disclosure and should remain possible when the source uploader loses the destination grant: either current source custody/export authority or a destination approver may withdraw. A destination approver need not obtain original access. Withdrawal cannot erase historical evidence. The UI must distinguish a historical command receipt from current publication status, preserve uncertain requests and reauthorize on refresh.

Source-only withdrawal remains available after partition changes and during preparation pauses. Authority to withdraw never grants private receipt visibility: a destination-only approver receives only sanitized publication and withdrawal fields. Scope grants currently require read as a prerequisite; raw malformed grants must not create a detailed approve-without-read path. Source-side management may expose opaque publication handles for inaccessible destinations, allowing withdrawal without disclosing destination labels, private reasons or other scope data.

Destination-only read requires a live scope read grant; downloading requires export as well. Published DTOs contain only disclosure ID, destination scope, publication time, output page count, content digest/size and current availability. They omit source IDs, source digest/page count, storage locators, preparation/review reasons, renderer internals and private actor information. Bytes themselves remain the explicitly reviewed derivative, including its visible page provenance caption. Destination lists are bounded and signed; withdrawn content is unavailable through both current and historical download URLs.

Qualification must cover actual source-only/destination-only users, all required grants and revocation/expiry, cross-tenant and raw-role denial, stale inspection/partition/artifact/hash, storage alteration, exact retries after withdrawal, conflicting races, transactional failure, retention/migration coverage and real browser source-to-destination use. The selected page can itself contain unrelated private material; the explicit disclosure review is mandatory and remains separate from financial acceptance.

## Implementation and evidence

Private immutable events alternate publication and withdrawal for each artifact/destination. A maximum of 100 transitions reserves the final transition for withdrawal. Runtime roles cannot read either evidence table or invoke private descriptor helpers directly; worker connections are rejected even when their role inherits an interactive function grant. Retained observations, including an observation whose final publication rolled back, block destructive downgrade. Both evidence tables participate in access coverage manifests.

The source publisher requires a deliberate target selection, opening the exact derivative, a reason and an explicit visible-content acknowledgment. A global destination view exposes active releases; a separate outgoing view lets the artifact creator withdraw using current source custody even when its inspection has changed or destination read rights are gone. The latter returns opaque destination handles when their metadata is inaccessible. No source reference, private review reason, renderer configuration or original hash is included in destination DTOs.

Uncertain commands retain exact request keys, bodies and expected heads. List refreshes may return no active release after a successful but lost withdrawal; that does not erase the retry. Definite permission denial clears protected pending publication state. Confirmed withdrawal invalidates any enclosing publisher availability claim and refreshes the target. Source metadata refresh and a historical command receipt are separate from current download permission.
